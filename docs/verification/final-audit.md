## Walkthrough observations

The pre-audit default-ref command was exactly the README command with a fresh destination named `generated`: published `npm create scaffold-hbar@latest`, unqualified `--template MrSufferer/scaffold-hbar`, Next.js frontend, Hardhat, npm, testnet, skip-install/skip-skills and yes flags. The gate resolved the public default before generation and checked it stayed stable afterward. It used neither local-source override nor author files.

In that generated project, `npm ci`, `npm run format`, `npm run check-types`, `npm test`, `npm run lint`, `npm run build` and `npm run start` passed. Production routes showed expected missing-configuration guidance. The browser deployed shipped bytecode on a disposable EVM, created and inspected invoices without a wallet, cancelled one, estimated separate fees, explicitly approved exact amount/round, verified atomic delivery/receipt, and reloaded saved pending/confirmed attempts. It also observed stale/invalid feed clearing, consensus quote expiry, insufficient funds, wallet rejection, changed account/network/round, confirmed revert and unknown outcomes. Each assertion is in [the shared journey][journey]; this is deterministic rehearsal, not real Hedera evidence.

The source CLI deployment at `0x3467c4A13171B1216691D37B2C3E69d05133E9e8` has [CLI evidence](2026-10-05-testnet-cli.json), including actual native-value transport, intended merchant delivery and cancellation. Earlier [real MetaMask evidence](2026-10-05-metamask.json) covers app source `7417838`. The diff to `efa23ae` changes wallet chain-ID validation; it therefore cannot simply inherit the earlier app result. The current-app rerun preserves the existing deployment because `git diff 3c8fe60 HEAD -- packages/hardhat/contracts packages/nextjs/lib/invoice-artifact.json` is empty. It reruns the affected wallet creation/quote/approval/payment/cancellation/reload journey. The current-app run settled invoice 6 in block 41375628 with 1,215,433,438 tinybars delivered atomically, reloaded its receipt, and cancelled invoice 7 in block 41375641. [Deployment verification][live] matches current compiled runtime (masking only compiler-declared immutable slots) and the intended merchant, recipient and feed. The [first failed attempt](2026-10-05-final-metamask-failed.json) remains recorded: invoice 5 creation succeeded, but validation failed before payment submission; no payment intent/hash was saved. An authoritative read found it open and unsettled before the independent fresh attempt. Later documentation-only changes require fresh generation, but do not change the proven contract or wallet behavior.
